All three approaches answered the same 32 test questions: 20 that a policy answers, 7 where the relevant policy exists but lacks the detail asked for, and 5 that no policy covers. Rules-based search is instant and uses no tokens, but because it only matches words, it found the right policy for 65.6% of the questions and gave an answer not backed by a policy covering the question in 28.1% (9 of 32). For example, it answered "Can I install Spotify on my work laptop?" with the Laptop Usage Policy and "Can I bring my dog to the office?" with the Office Access Policy. It cannot invent facts, since it quotes policies verbatim, but it confidently returns the wrong rule whenever the question uses other words than the policy ("journalist" instead of "media"). Both LLM approaches (Claude Opus 5.5) found the correct policy for almost every question, and a separate Claude judge that saw the whole database found no unsupported claims in either. When a policy lacked the detail asked for (the number of sick days, the approved carriers, a meal allowance), they said so instead of guessing, and they declined all five out-of-scope questions. Sending the whole database with every question costs about 4,991 tokens per question, against 735 with the vector index (85% fewer), or roughly $0.021 against $0.004 per question. The vector-index version was also slightly faster (median 2.15 s against 2.53 s), because a shorter prompt is processed faster.

My preferred approach is the LLM with a vector index, which is also the approach the Slack bot uses. It matches the accuracy and groundedness of sending the whole database while using about a seventh of the tokens. Unlike the whole-database approach, its cost and response time do not grow with the size of the policy collection: 98 one-sentence policies fit easily in a prompt, but a real employee handbook with hundreds of pages would not. Its weakness is retrieval. For "I clicked a suspicious link and think my laptop is compromised", the three retrieved policies did not include the Security Incident Policy, so the model answered that no policy covered the question. This failure is safe, because the model declines rather than inventing an answer. It could be reduced by retrieving more policies or by combining vector search with keyword matching. Rules-based search is only worth keeping as a fast, free fallback, for example when the API is unavailable, since more than a quarter of its answers would point employees to the wrong policy.
